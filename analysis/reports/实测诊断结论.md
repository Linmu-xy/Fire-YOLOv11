# Fire-YOLOv11 实测诊断结论

日期：2026-09-30　机器：lxy-System（RTX 3090 24GB）　环境：conda `yolo11`

**全部结论来自本机已有的 run 与标签，没有新增任何训练。** 所有数字可用 `analysis/` 下的脚本复现。

---

## 一、结论摘要

1. **P2 的结构性余量只占 5.9%（D-Fire val）/ 3.1%（FASDD_CV val）。** 也就是说 P2 唯一能负责的那一档目标，在两套数据里都极少。
2. **这套实验装置的测量门槛是 0.73–1.05pp。** 而 P2、SRDG、DCBR、ACR 的实测效应分别是 +0.68 / +0.39 / +0.45 / +0.15pp，**全部低于门槛，均不显著**。
3. **唯一越过门槛的改动是输入分辨率（960，+1.21pp），不是任何网络结构改动。**
4. 分层评估显示：**P2 的微弱优势出现在大目标档（+0.96 / +1.06pp），而不是它本该负责的小目标档（+0.68pp）** —— 支持"收益来自额外容量"而非结构必要性。

## 二、P2 的结构性余量（可测量的命题一）

`gt_size_distribution.py`，imgsz 640。判据：letterbox 后长边 < 16px（stride 8 需要至少 2 格）。

### D-Fire

| split | 图像数 | GT 框 | P3(stride8) 不充分占比 | 其中连 P2(stride4) 也不充分 |
|---|---:|---:|---:|---:|
| train | 15,485 | 19,197 | **6.8%** | 0.7% |
| val | 1,722 | 2,091 | **5.9%** | 1.0% |
| test | 4,294 | 5,160 | **7.4%** | 1.0% |

letterbox 后长边分位（val）：p10=20.0　p25=36.5　**p50=81.9**　p75=238.0　p90=427.9

### FASDD_CV

| split | 图像数 | GT 框 | P3 不充分占比 | 连 P2 也不充分 |
|---|---:|---:|---:|---:|
| train | 47,660 | 66,563 | **3.3%** | 0.3% |
| val | 31,770 | 42,548 | **3.1%** | 0.2% |
| test | 15,884 | 17,242 | **1.7%** | 0.1% |

letterbox 后长边分位（val）：p10=27.3　p25=56.5　**p50=131.4**　p75=248.8　p90=419.7

**两次推翻预设：**
- 原本猜测"FASDD_CV 是高分率集（图像宽 78–10,600px），应该有真正的小目标，P2 可能在那里有用"。**实测相反**：FASDD_CV 的目标在 letterbox 后反而**更大**（val 中位数 131px vs D-Fire 82px），P2 作用域更小。
- 脚本内置判读阈值是 15%，两套数据都远低于它 —— 结论是统一的：**P2 缺结构性必要性。**

### 火与烟是两个完全不同的尺度故事

| 数据集 | fire 的 small 占比 | smoke 的 small 占比 |
|---|---:|---:|
| D-Fire val | 31.2% | **3.9%** |
| FASDD_CV val | 33.6% | **2.3%** |

smoke 有 75–82% 是 large。**任何以"小目标"为卖点的故事，都必须分类别讲，且只对 fire 成立。**

### 顺带一个对"降误报"有用的数

无标注（背景）图像占比：D-Fire train 45.5% / val 45.9% / test 46.7%；FASDD_CV 约 41%。数据集本身的负样本比例已经很接近你协议里要报的口径。

## 三、这套装置能分辨多大的效应（可测量的命题二）

`metric_power_analysis.py`，只读 results.csv。

### 方差分解

| 配置 | 种子数 | 组间 σ（seed 间） | 组内 σ（epoch 间） | 比值 | **MDD (α=0.05)** |
|---|---:|---:|---:|---:|---:|
| `paper-v1/dfire/p2` @640 | 3 | 0.4218pp | 0.0752pp | **5.6×** | **1.0478pp** |
| `yolo11n/D-Fire`（历史基线）@640 | 3 | 0.2952pp | 0.0572pp | **5.2×** | **0.7333pp** |

**组间 σ 是组内 σ 的 5 倍以上。** 含义：波动来自初始化与优化轨迹，不是评估噪声。
→ 把验证做得更精细、对多轮取平均，**都不会降方差**；只有加独立种子或改用配对设计才有效。

### 各指标的分辨率对比（原本预期"换个终点就能救命"）

| 指标 | 组间 σ | **MDD** | 可行性 |
|---|---:|---:|---|
| `metrics/precision(B)` | 0.0862pp | 0.2141pp | ⚠️ 每个 run 重调阈值，跨 run 不是同一工作点，不可用作终点 |
| `metrics/mAP50-95(B)` | 0.2952pp | **0.7333pp** | 四列里最优 |
| `metrics/mAP50(B)` | 0.4360pp | 1.0832pp | 比 mAP50-95 更差 |
| `metrics/recall(B)` | 1.0010pp | 2.4869pp | 最差 |

**这里推翻了一个早先的判断**：原本预期 mAP50 的种子 σ 会明显小于 mAP50-95（因为 mAP50-95 含高 IoU 定位成分）。实测相反，mAP50 的种子 σ 更大。

→ **在 results.csv 现有的四列里"换终点"没有出路。** 要降门槛必须换到 `firesmoke/reliability.py` 那套图像级告警指标（固定每类 1% 负图 FPR 预算下的 recall、`background_alarm_fraction`、图像级 ECE/Brier），**而这套指标用已有 checkpoint 就能算，不用重训**。这是下一步最该做的事。

### 要检测给定效应需要多少种子（按组间 σ = 0.2952pp 反算）

| 目标效应 | 所需独立种子数 |
|---:|---:|
| 1.00pp | 2 |
| 0.50pp | 3 |
| 0.30pp | 4 |
| 0.10pp | 12 |

## 四、效应对照：只有分辨率越过了门槛

参照 = `outputs/paper-v1/dfire/baseline/seed0`（同协议 640）。

| 配置 | 效应 | 是否越过门槛 |
|---|---:|---|
| `paper-v1_960/dfire/baseline` | **+1.21pp** | ✅ 唯一越过的 |
| `paper-v1/dfire/p2` | +0.68pp | ❌ < 1.05pp |
| `paper-v1_800/dfire/baseline` | +0.60pp | ❌ |
| `module-dcbr-v1/.../p2_dcbr` | +0.45pp | ❌ |
| `module-srdg-v1/.../p2_srdg` | +0.39pp | ❌ |
| `module-acr-v1/.../p2_acr` | +0.15pp | ❌ |
| `yolo11n/D-Fire`（历史基线） | +0.05pp | ❌ |

**注意 960 那一条仍是单种子对单种子。** 按 640 的种子 σ 估计，两个独立单种子之差的 σ ≈ √2 × 0.42 ≈ 0.60pp，所以 +1.21pp 约 2.0σ，勉强够，但没有 3 个种子就不算验证。

**已达成可检测阈值的效应，全部来自输入分辨率，没有一个来自网络结构改动。** 这是本次最干净的一条结论，而且它本身就是可以写进论文的东西。

## 五、分层评估：P2 的优势出现在大目标档

`stratified_ap.py`，D-Fire val，imgsz 640，P2 seed0 vs 640 基线 seed0。
口径：按 letterbox 后长边分档，档外 GT 按 COCO 规则忽略（匹配上的检测不算 FP 也不计召回）。

| 档位 | class | n_gt | P2 AP50-95 | 基线 AP50-95 | Δ |
|---|---|---:|---:|---:|---:|
| lb0–8px | fire | 19 | 0.28% | 0.55% | −0.27pp |
| **lb8–16px** | fire | 95 | 2.67% | 1.99% | **+0.68pp** |
| lb16–32px | fire | 249 | 16.03% | 15.07% | +0.96pp |
| **lb≥32px** | fire | 767 | 46.73% | 45.67% | **+1.06pp** |
| lb0–8px | smoke | 1 | 0.00% | 0.00% | 0 |
| lb8–16px | smoke | 8 | 0.58% | 0.56% | +0.02pp |
| lb16–32px | smoke | 76 | 8.01% | 8.52% | −0.52pp |
| lb≥32px | smoke | 876 | 54.59% | 54.49% | +0.10pp |

**两个判读：**

1. **P2 的微弱优势出现在大目标档**（fire lb≥32px +1.06pp、lb16–32px +0.96pp），
   而它本该负责的 lb8–16px 档只有 +0.68pp。**这支持"收益来自额外容量，而非结构必要性"。**

2. **lb8–16px 档的 AP 只有 2–3%，lb0–8px 只有 0.3–0.5%** —— 这些目标实质不可检测。
   换算到原生（416，缩放 1.538）它们是 **5.2–10.4px** 的框。在 416px 图上只有 5–10 像素的
   "火"，**其中相当一部分很可能是标注噪声，而不是"需要更高分辨率才能看见的目标"**。
   这条要单独查：抽几十个 lb<16px 的框看图，确认是真实火苗还是标注伪影。

### 定量上界（本次最有说服力的一条）

fire 的 <16px 档占该类框数的 10.1%，P2 在该档的相对优势是 0.68pp：

```
对整体 mAP 的贡献 ≈ 0.68pp × 0.101 ÷ 2（两类平均）≈ 0.03pp
```

- 而测量门槛是 **1.05pp**
- **两者相差约 35 倍**

即便把 <16px 这一档修到完美（AP → 1.0），整档对整体 mAP 的全部贡献也只有约 0.14pp，仍不到门槛的 1/7。

**结论：P2 在 D-Fire 上不可能产生可测量的收益。这不是运气问题，是算术问题。**

### 自校验

本脚本全量 mAP50-95 = 0.47587，`yolo val` = 0.48384，差 0.80pp（在 1pp 阈值内）。
差异来自 COCO 101 点插值与 ultralytics 匹配循环的实现差别，以及 conf/iou 口径。
解读分档结果前先接受这个量级的口径差。

## 七、行动清单（按成本排序）

1. **补完 1280 的 run**（1 次续训）。它现在停在 55 轮，而这是回答"提分辨率还有没有收益"最关键的缺失数据点。
2. **给 800 与 960 各补 2 个种子**（4 次训练）。目前唯一有信号的改动就是分辨率，但它只有单种子证据。补完之后这条线就能写成可信结论。
3. **测 `reliability.py` 图像级指标的种子 σ**（0 次训练，只跑推理）。这是唯一可能把门槛从 1.05pp 降到可用的方向。用第 3 节的同一套方法先量它的门槛，别想当然。
   ```bash
   python analysis/metric_power_analysis.py --root outputs experiments --metric "metrics/mAP50-95(B)"
   ```
4. **抽查 lb<16px 档的标注质量**（人工看几十张图）。如果多数是噪声，那么"小目标"这条叙事要整体放弃。
5. **把 P2 写进论文的负面消融**，配上第 2 节的 5.9%、第 5 节的定量上界、以及"优势出现在大目标档"这条观察。
   这比"P2 涨了 1 个点"有说服力得多，而且完全经得起审。
6. **暂时不要自建高分辨率数据集。** 依据：FASDD_CV 已经是高分率集，它的 P2 余量（3.1%）比 D-Fire（5.9%）**更低**。在拿到第 3 步的结果之前，建数据集是在赌一个已被两套数据否证的机制。

## 八、复现命令


## 九、两个必须记住的坑

1. **必须 `export PYTHONPATH=$PWD`。** checkpoint 里 pickle 了对自定义模块 `firesmoke` 的引用，
   从 `analysis/` 目录直接跑会报 `ModuleNotFoundError: No module named 'firesmoke'`。
2. **必须分块推理（`--chunk 128`）。** 一次性把 1722 条图像路径交给 `model.predict(source=[...])`，
   会被 ultralytics 预加载成一个巨 batch，单次 forward 尝试分配 5.26 GiB → CUDA OOM（实测踩到）。
