## 1. 核心设计原则（三条，不可妥协）

1. **固定一切能固定的**：`imgsz=640`、`batch=32`、`optimizer=SGD`、`lr0=0.01`、`epochs=100`、
   `deterministic=true`、`close_mosaic=10`、`amp=false`。**只有数据构成变化。**
   这样现有 `paper-v1/dfire/baseline/seed0`、`D-Fire_p2_seed0/1/2` 可直接复用为对照。
2. **每配置 3 个种子。** 实测 `n=2` 因 t(1)=12.706 基本无效。
3. **主终点换成跨域图像级告警指标，且所有变体共用一个阈值。**
   每种子重选阈值会把门槛从 0.34pp 抬到 3.18pp。

## 2. ⚠️ 数据改动的实现路径（关键约束）

`firesmoke/data.py: load_prepared(verify=True)` 有四重硬校验，**任何数据构成改动都无法手工完成**：

```python
digest(out/"manifest.jsonl") != metadata["manifest_sha256"]   → raise "Prepared manifest was modified"
read_labels(...) != r["boxes"]                                 → raise "Prepared label changed"
(out/f"{split}.txt").read_text().splitlines() != expected      → raise "Prepared split changed"
data_yaml != {"path":..., "train":"train.txt", ..., "names":...} → raise "Prepared data.yaml changed"
```

**因此负样本过采样不能靠改 `train.txt` 或 `data.yaml` 实现。** 必须：

1. 在 `firesmoke/data.py` 的 `prepare()` 里加一个参数，例如 `neg_repeat: int = 1`，
   在写 `manifest.jsonl` / `{split}.txt` 时把**纯背景图的行重复 `neg_repeat` 次**
   （`excluded.json` 与 `metadata.json` 同步更新，保持校验自洽）。
2. 在 `configs/protocol.yaml` 的 `datasets:` 下新增一个条目，例如：
   ```yaml
   dfire_hn:            # hard-negative 加强版
     root: datasets/D-Fire
     layout: dfire
     source_names: [smoke, fire]
     invalid_box_policy: exclude_invalid_images
     neg_repeat: 3      # 新增字段
   ```
3. 跑 `prepare --dataset dfire_hn` 生成 `artifacts/data/dfire_hn/`，然后正常 `train --dataset dfire_hn`。

**注意**：D-Fire train 里纯背景图有 **7,043 张**（45.5%）。重复 3 次 → 有效背景曝光 ×3。
这**不是"补数量"**，而是把背景梯度权重提高——因为实测显示 45.5% 的背景图不足以教会模型
"红球花不是火"。

## 3. 消融矩阵

### 阶段 1（推荐先做，1 个新数据集 + 5 次训练）

| # | 配置 | 数据 | 目的 | 次数 |
|---|---|---|---|---|
| A0 | `baseline640` | D-Fire train | 对照（**已有 seed0**） | +2（seed1,2） |
| A1 | `dfire_hn3` | D-Fire train，背景图 ×3 | 测 G2 数据侧 | 3 |

**为什么先只做 A1：** G2 的证据最直接（误报 3.4:1 偏火侧 + 人工确认是红色物体），
实现路径清晰（只改 prepare 的一个参数），且**不需要任何外部数据集**。

**成本**：5 × ~1.9h ≈ **9.5 GPU 小时**。两台机器分摊约 5 小时墙钟。

**判定**：
- 主终点：跨域（FASDD test）背景告警比例。门槛 **1.37pp**，基线 9.5–12.3%。
- 若降到 **<7%**（即改善 ≥3pp，约 2×门槛）→ 有效，进入阶段 2。
- 若改善 <1.37pp → **停**，说明源域背景图重复无用，必须换数据来源（见阶段 2 备选）。

### 阶段 1-B（修订：改用 FireSmoke-YOLO 负样本）

**2026-10-01 新增测量（`analysis/scripts/probe_negatives.py`，基线 seed0 权重，冻结阈值 fire=0.3148/smoke=0.6060）：**

| 负样本来源 | 张数 | **任意类告警率** | fire 分数 p99 | smoke 分数 p99 |
|---|---:|---:|---:|---:|
| D-Fire val 自身背景（参照） | 790 | **0.25%** | 0.093 | 0.311 |
| **FireSmoke-YOLO val 负样本** | 330 | **2.42%** | 0.159 | 0.672 |
| **FireSmoke-YOLO test 负样本** | 330 | **3.33%** | 0.417 | 0.596 |
| FASDD test 负样本（目标） | 6,533 | 9.5–12.3% | — | — |

**这个测量决定了设计**：
1. 模型对 D-Fire 自己的背景已**几乎全对**（0.25%）→ 所以 A1（`dfire_hn3` 只加重这些背景的权重）
   **确实没有信息增量**，用户停掉它的判断正确。
2. **FireSmoke-YOLO 的负样本比 D-Fire 背景难约 10 倍**（2.9% vs 0.25%）→ **它们携带新信息**，
   方向正确。
3. 但仍低于目标域的 10% → **是"较弱版本"的目标失效模式**，不是完全复现。

**规模差异值得注意**：D-Fire 背景是**精选监控画面**（0.25%），FS 负样本是**新闻/网络图**（2.9%），
FASDD 负样本是**网络爬取随机图**（10%）。→ 失效模式是
**"模型没见过互联网随机图像，把其中的暖色物体当火"**，而 FS 属于同一类数据、只是没那么多。

**Arm B 设计（修订）**：

| 项 | 设定 |
|---|---|
| 训练数据 | D-Fire train（15,485）+ FireSmoke-YOLO **train 负样本**（1,539）× **R 次** |
| 变量 | R（剂量）。建议 **R=3** → train 行数 20,102（+29.8%），背景占比 45.5%→52.2% |
| 只并入 train | val/test 保持 D-Fire 原样，保证域内指标可比 |
| 实现 | 在**源目录层面**合并（symlink FS 负样本 + 空标签），**无需改 `prepare` 代码**；类别顺序冲突不存在（负样本无框） |
| 种子 | 0 / 1 / 2 |
| 成本 | 约 628 batches/轮 → ~1.3 min/轮 → **约 6.5 h / 3 runs** |

**预期（诚实区间）**：跨域背景告警从 ~10% 降到 **6–9%**，即改善 **1–4pp**。
门槛 1.37pp → **有较大概率可分辨**，但不像"必定有效"。
比 A1 的胜率高得多（A1 预计 <1.4pp 不可分辨）。

**已知限制**：
- FS 负样本仅 1,539 张（train），量偏少，所以需要 R>1 的剂量提升
- FS 负样本的 fire/smoke 触发构成不一致（val 以 smoke 为主 7:1，test 以 fire 为主 8:2，n 很小）
- 图像带中新网/Alamy **水印**，须在报告中注明
- **与 D-Fire/FASDD 的同源近重复审计尚未做** → 接入前必须跑

### 阶段 2（可选，按阶段 1 结果决定）

**G1（跨域烟召回）必须换数据，因为 D-Fire 的烟外观单一**（75% 是 large、来源集中）。
但**把 FASDD 加进训练会毁掉它作为未见域的地位**。两条路：

| 路线 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **2a** | 保持 FASDD 未见；改用 **MS-FSDB** 或 **PyroNear2024** 的烟补多样性 | 需下载第 2 个数据集 | 需先审计其 train/test 是否 scene-disjoint |
| **2b** | 把 **FASDD_CV train** 当第二源域（含 19,600 张类火负样本，正好补 G2） | FASDD 变可见 | **必须另留一个未见域**（MS-FSDB / PyroNear / ONFIRE / FIgLib） |

**2b 的诱惑很大**：FASDD train 的 19,600 张 `neitherFireNorSmoke` 里就包含那些红花/隧道/雾的图，
等于一份现成的类火负样本库；同时它的烟更杂，正好打 G1。**但代价是失去最重要的测试域。**
若走 2b，测试域建议选 **MS-FSDB test**（12,586 张，含刻意挑选的困难负样本，是正式 benchmark）。

### 阶段 3（只有在 1、2 都见效后才做）

在固定的 `dfire_hn3` 配方上，把结构模块（P2）重新跑一遍——此时终点门槛已降到
跨域告警 1.37pp，P2 那 +0.68pp 仍然测不出，**所以预期依然是负面结果，不建议做。**

## 4. 终点与统计（必须照做）

**主终点（跨域，目标域 = 未见来源）**
1. `background_alarm_fraction` — 背景图任意类触发比例
2. `smoke_only 图像的召回` — 按图像类别分开报，**不要和 both 混**
3. `fire 召回`（作为"没变差"的守卫指标）

**副终点**：跨域 mAP50-95、域内 mAP50-95（用于与文献对话）

**统计要求**
- 阈值：**所有变体共用一个阈值**，取自 `baseline640/seed0` 的**源域 val**，1% FPR 每类。
  报告时并列说明由此导致的 FPR 轻微偏移。
- 报告 **mean ± 种子 σ**，并给出该终点的 MDD（`t_crit(n-1)×σ/√n`）。
- 任何小于 MDD 的改善**不得称为提升**。

**必须分开报告的拆分**（否则机制被平均掉）：
- 按图像类别：`smoke_only` / `both` / `fire_only` / `none(背景)`
- 按目标尺寸档（letterbox 后长边）：`<32 / 32–64 / 64–128 / ≥128px`
  —— 因为实测烟雾召回在 `64–128px` 档出现异常低谷（跨域仅 14.7%，而该档占跨域烟框 41.8%），
  不拆开就会看不见。

## 5. 边界与协议

1. **域划分**：训练域 ⊆ {D-Fire train, FASDD train, 新数据 train}；测试域必须是**完全未参与训练**的
   一个数据集。当前最干净的是 FASDD test（阶段 1 可保持）。
2. **每个拟采用的数据集先跑一次完整性审计**（`analysis/split_integrity_audit.py --emit-manifests`）。
   D-Fire 与 FASDD 官方都是随机划分，已知 D-Fire test 有 46% 近重复泄漏。
   **FASDD 的审计尚未做**（`prepare` 用的是官方 YOLO 划分清单）。
3. **测试集不得用于任何选择**（阈值、epoch、超参）。现有 `run.json` 已记录 `selection: "best validation mAP50-95"`，保持。
4. `deterministic=true` 已在协议里，保留。

## 7. 停止规则（预先登记，避免无限试）

1. **阶段 1 若背景告警改善 <1.37pp** → 停止"加数据"这条线，转做**任务重定义**
   （例如把终点改为"仅在 smoke-only 场景下评估"，或改用固定场景相机做域内评估）。
2. **任何配置的域内 mAP50-95 下降 >0.92pp** → 该配置判为伤害检测能力，不采用，
   即使它在告警指标上更好（必须两者同时报）。
3. 阶段 2 若跨域 smoke_only 召回在**同尺寸档内**提升 <5pp → 判定"烟的多样性"不是瓶颈，
   转而检查 FASDD 的标注一致性（`64–128px` 档的异常低谷需要人工看图确认）。
