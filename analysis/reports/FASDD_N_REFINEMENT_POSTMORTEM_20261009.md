# FASDD YOLO11n：本次模块训练复盘

日期：2026-10-09。对象：cmj 的 context seed0、lxy 的 detail seed0，均完成 100 轮。所有“点”均指绝对百分点。

## 1. 结论

最终指标确实几乎没有改善。但这两次训练经历了有缺陷的续训，不能作为正常、连续训练的模块消融结论。

1. **确定存在续训缺陷**：自定义入口在恢复训练时再次执行“只迁移层 0–22”的初始化政策。骨干和颈部恢复了，检测头与新增模块被重新初始化；旧 optimizer 和 EMA 随后被恢复。这个问题出在自定义续训实现。此前“正确续训”的判断错误，检查只覆盖了轮次、优化器和 EMA，没有核对训练模型的完整权重。
2. **确定 detail 在最终模型中几乎不起作用**：全验证集关闭 detail 后，mAP50–95 仅变化 0.0000022 点；其回归残差约为原 P3 特征的百万分之一。
3. **确定 context 在最终模型中起作用，但没有证明优于独立基线**：关闭 context 后下降 2.476 点，说明共同训练的网络依赖它。这个数字不能解释为模块给基线带来 2.476 点收益。
4. **暂停前也没有明显优势**：最后十个完整轮次的平均同轮差值为 detail +0.0646 点、context +0.0227 点。修复续训不能自动保证大幅收益。

现有证据不支持“主要原因确定是通道数”或“修复后一定能提高 5 点”。

## 3. 续训如何改变了实验

### 3.1 实际代码路径

安装版本为 Ultralytics 8.4.42，读取实际安装源码：

```text
BaseTrainer.setup_model
  → load_checkpoint(last.pt)
  → ResearchTrainer.get_model(cfg=weights.yaml, weights=weights)
      → 新建 ResearchModel
      → shared_transfer：只复制 model.0 到 model.22
      → 安装一个新建的 refinement
  → 建立 optimizer 和 EMA
  → resume_training / _load_checkpoint_state
      → 恢复 optimizer、scaler、EMA、best_fitness
```

`_load_checkpoint_state` 没有再恢复训练模型的 state_dict。官方普通 Trainer 会在 get_model 中加载模型权重；我们覆写后应承担完整恢复的责任。原入口错误地把“预训练初始化政策”用于“同一模型断点续训”。

后果是：旧模型的优化器动量对应新初始化的检测头/模块；旧 EMA 又逐渐混入这个发生重置的训练模型。曲线先缓慢下跌、数轮后到达低谷，与这一机制一致。

### 3.2 曲线断点

|---|---:|---:|---:|---|---:|
| detail | 24 | 48.941% | 25 | epoch32，40.587% | −8.979 点 |
| context | 29 | 49.445% | 30 | epoch39，42.954% | −7.084 点 |

context 的 train box/cls/dfl loss 在 29→30 轮从 1.2729/1.2690/1.4462 跳到 1.4219/1.4595/1.6400；detail 在 24→25 轮也有同向跳变。随后大段训练用于恢复性能，100 轮结果逐渐接近基线。

检查范围是实际检查点的结构/状态恢复和预测一致性；本轮没有启动 Trainer 训练，也没有执行新的暂停/恢复训练实验。原实验仍标记完成，性能记录保留；本报告指出其模块归因限制。

## 4. detail 的独立分析：最终支路近乎休眠

### 4.1 全验证集关闭模块

只在内存中绕过 refinement，其他共同训练的权重保持相同，验证协议完全一致：

| detail 检查点 | mAP50–95 |
|---|---:|
| 原模块开启 | 53.214733% |
| 临时关闭 | 53.214731% |

变化 **0.0000022 点**。这是当前模型几乎不依赖 detail 的直接证据，不需要通过参数量猜测。

8 个真实矩形验证 batch（512 张，排除后端合成 warmup）的 P3 回归残差/原特征 RMS 平均为 **1.168×10⁻⁶**。P4/P5 回归和全部分类分支均没有 detail 残差，符合实现。门控 sigmoid 均值 **0.4980**，未显示门控饱和到关闭状态。

### 4.2 信号在哪些位置变小

另取固定哈希排序的 128 张 val 图，背景/仅火/仅烟/混合各 32 张，使用 640 方形输入、未融合 FP32 模型。该平衡样本用于检查信号，不用于估计数据自然占比。

| 位置 | 平均 RMS |
|---|---:|
| 原 P2 输入 | 1.2321 |
| reduce 卷积输出 | 0.13894 |
| mix 卷积输入：SiLU 后、PixelUnshuffle | 0.07149 |
| mix 卷积输出 | 0.008921 |
| local 卷积输入：SiLU 后 | 0.004451 |
| local 卷积输出 | 0.0006193 |
| 最终 output 输入：SiLU 后乘门控 | 0.0001546 |
| 最终细节残差 | **7.268×10⁻⁷** |
| 原 P3 特征 | 0.76870 |

PixelUnshuffle 本身是重排，不应被归咎为直接丢信息。实际支路串联了多次通道压缩、无归一化卷积和 SiLU，乘上约 0.5 的门控，再经过小输出投影。

### 4.3 参数有没有学到明显的新方向

以记录 seed0 重建旧恢复入口得到初始化参考：

- reduce/mix/local/gate/semantic 权重与参考的方向余弦均约 **0.999981–1.000000**。
- 拟合为参考权重的缩放后，尺度约 **0.2275–0.2278**。
- gate bias 尺度约 0.99975；卷积权重参加 weight decay，bias 不参加，观察结果与弱任务梯度下持续权重衰减相符。

初始化参考是路径重建，未冒充历史初始化快照；也没有历史逐步梯度记录。可以判断当前分支学习的新方向极小，但不能精确分解各阶段梯度和续训重置造成的影响。

零初始化输出在第一步使上游支路任务梯度为零，这是设计事实；context 同样零初始化却学到了明显残差，所以**零初始化单独不能解释两者差异**。需要检查的是长串联低幅信号与重置后低学习率、旧动量的共同影响。

### 4.4 与 FASDD 目标的匹配

detail 只影响 P3 回归。它读取 stride4 特征后压到 stride8，预测网格仍是 stride8/16/32，共 8,400 个位置；没有增加更密集的预测位置，也没有直接加强分类特征。

既有基线诊断显示火焰同时存在漏检与定位问题。只给 P3 回归增加当前这种极弱残差，难以覆盖这些问题。隐藏宽度16值得做独立对照，但现在最直接的证据是信号/学习近乎消失，而不是通道数已被证明不足。

## 5. context 的独立分析：有功能依赖，未产生额外收益

### 5.1 全验证集关闭模块

| context 检查点 | mAP50–95 |
|---|---:|
| 原模块开启 | 53.268630% |
| 临时关闭 | 50.792841% |
| 关闭后下降 | **2.475789 点** |

fire AP50–95 从 44.766% 变为 42.066%，smoke 从 61.771% 变为 59.519%。模块确实参与最终预测。

绕过模块后，分类/回归头收到训练时不习惯的特征。这个实验测的是当前共同训练模型的依赖，不能替代独立训练 baseline 与 context 的配对消融，也不能将下降写成模块提升。

### 5.2 学到的残差与路由

8 个真实 val batch 平均残差 RMS / 原特征 RMS：

| 输出层 | 回归残差 | 分类残差 | 来源 P3/P4/P5 平均路由权重 |
|---|---:|---:|---|
| P3 | 29.12% | 18.62% | 0.412 / 0.446 / 0.142 |
| P4 | 24.83% | 24.62% | 0.176 / 0.128 / 0.696 |
| P5 | 7.17% | 3.27% | 0.120 / 0.141 / 0.738 |

这些数值排除了“context 也完全没被用上”的解释。路由并非均匀，但抽样均值不能证明逐目标选择正确，不能据此宣称自适应路由带来了收益。

baseline 已包含 SPPF、C2PSA 和 PAN 上下行融合。额外低维融合可能与这些能力重叠，或改变了参数分工却未增加有效能力，这是合理假设。当前续训污染也可能遮蔽正常收益，仍需干净训练区分。不能直接确定“16通道压缩太严重”或“融合导致过平滑”。

## 6. 数据与目标：应该改善什么

沿用 2026-10-08 的完整基线诊断，以下为两 seed 均值，不用于代替本次 seed0 配对差值：

- fire AP50–95 44.808%，smoke 61.985%；fire AP50/AP75 为 74.370%/45.945%。严格定位仍是明显薄弱项。
- 火焰长边投影到640后，<16px 仅占3.68%；16–64px 占37.83%。仅优化最小目标不能覆盖主要误差。
- 固定 conf=.25 时，16–32px 火焰 IoU.5/.75 召回42.83%/18.35%；32–64px 为59.56%/36.90%。这些诊断召回不能当作AP。
- 火烟混合场景的烟雾召回更差，定向样例可见合并/拆分火簇和烟羽边界差异；还不能断言这些标注问题占了多少错误。
- 工业烟羽负图是否错误标注取决于类别政策，需明确“烟雾”任务定义。
- train 中 fire 框33,137、smoke22,869，不能按框数把 fire 简单当作少数类。

两条新分支都没有改变检测网格、标签粒度、样本分布或原有定位监督。增加注意力/融合并不会自动修复这些缺口。参数数量依然属于 n 规模：baseline2,590,230，detail2,594,998（+0.184%），context2,613,375（+0.894%）。

原 CUDA profile 中 detail 延迟增加约2.4–7.0%，context约16.2–20.1%。这是先前固定 FP32/batch1/640 的工程测量，不是本次 val speed 的比较。

## 7. 下一步方案：保持 n 规模

### 第一优先级：建立可信对照

已修复完整模型恢复。下一轮使用新的实验 tag，固定 clean-v1、seed0、640、100轮与迁移政策。对仍有明确功能的 context 做一次干净训练；若发生暂停，逐张量验证恢复并保留输入检查点。现有被污染的结果作为历史记录保留。

完成的 last.pt 已剥离优化器，不能把从它延长训练当作恢复原实验。重新建立可信曲线需要从相同初始条件重新运行。

### 第二优先级：重新设计可学习的细节旁路

建议先验证最短、带归一化的旁路：

```text
P2 → PixelUnshuffle(2) → 1×1 Conv+BN+SiLU
   → 3×3 depthwise Conv+BN+SiLU → 输出投影 → P3回归
```

先移除额外串联压缩和门控，记录每轮激活/残差 RMS、任务梯度、权重范数。隐藏16/32作为独立消融；将浅层细节提供给分类分支作为后续单独对照。保持原三层64/128/256输入和原预测器宽度，不改变 n 主干。

归一化/短路径是待验证方案，不是已证明的提升。输出初始化也应单独比较：零输出与有界小幅非零输出，检查训练起步和最终AP，避免一次改变多个因素后无法归因。

### 第三优先级：结合误差调整模块位置

对候选固定报告 fire AP75/AP50–95、16–64px火焰召回、混合场景烟雾召回。若干净 context 仍没有收益，降低其训练预算，优先定位/分类细节路径；现在不适合直接把休眠的 detail 与 context 叠加后期待5点。

从训练集按来源抽样审核火簇合并/拆分、烟羽边界和混合场景，先明确政策再决定是否建立新数据版本。所有兼容检测头预训练迁移可作为独立的 n 模型配方对照；不要与模块改变同时归因。

### 第四优先级：检验稳定性

seed0 有明确改善后补齐 seed1/2，与各自基线配对。+5点目前是目标，没有证据保证某一个模块能达到。保持val筛选口径；本次没有用test选择模块。
