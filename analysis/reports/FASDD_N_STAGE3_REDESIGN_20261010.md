# FASDD YOLO11n：V2 终局检查与下一阶段实验

日期：2026-10-10。所有“点”均为绝对百分点。部署模型继续保持 n 规模。

## 1. 判断与证据范围

V2 的收益确实很小，不能把分支“有梯度、有残差”解释成准确度有实质改善。本次对 baseline seed0、context seed0、detail_norm seed0 完成相同口径的全 val 重评，并为 baseline/context 补充排序诊断。当前最值得优先验证的新假设是：**预测分数与框的严格定位质量存在错配**。真实几何定位、样本难度和标注粒度也仍有缺口，排序诊断不能排除它们。

两组 V2 的训练记录均完整包含 epoch1–100、数值有限、launch status=completed/returncode0；训练核心 models.py、pyramid_refinement.py、detail_refinement_v2.py、checkpoint_state.py 与启动时保存的 SHA256 一致。数据内容和预训练权重指纹一致，没有 pause.json。曲线没有 V1 那种检测头重置后损失突跳的断点。现有证据不支持把这次低收益归因于 V1 的续训缺陷。

固定重评：Ultralytics8.4.42；val29,804 张、36,458 框；640、rect=true、batch64、conf=.001、NMS IoU=.7、max_det300、FP32、augment=false。候选检查点在诊断前后的 SHA256 相同。全 val 重评与 CSV 相差不到0.004点，以下两种口径分别标明。

## 2. 模块没有改善预定的主要短板

| 方法，seed0 | CSV mAP50–95 | 相对原基线 | 重评 fire AP75 | 重评 fire AP50–95 | 重评 smoke AP50–95 |
|---|---:|---:|---:|---:|---:|
| baseline | 53.265% | — | 45.895% | 44.735% | 61.792% |
| context | 53.484% | +0.219点 | 46.008% | 44.890% | 62.074% |
| detail_norm | 53.365% | +0.100点 | 45.873% | 44.814% | 61.910% |

context 的 fire AP75 仅增加0.113点，detail_norm 反而下降0.022点。context 后10轮平均同轮增益为0.258点，detail_norm 为0.138点；收益不是只在某个偶然峰值出现，但幅度仍然不足。baseline seed0/1 的历史差值为0.265点，这只是两个 seed 的观察差异，不是显著性阈值或随机波动上界。

固定 conf=.25 的专项诊断进一步显示：

| 诊断量，非 AP | baseline | context | detail_norm |
|---|---:|---:|---:|
| 16–64px 火焰 IoU.75 召回 | 29.970% | 29.957% | 28.924% |
| 混合场景 smoke IoU.5 召回 | 56.747% | 57.110% | 56.617% |
| 背景图告警率 | 2.320% | 2.212% | 2.181% |

16–64px 火焰是 detail 的关键目标，但严格定位召回没有改善。detail_norm 的约1.046点下降仅是这一固定阈值诊断量，不能写成全 AP 下降1.046点。

### detail_norm 的限制

前8个真实矩形 val batch 中，P3 回归残差/原特征 RMS 平均为12.615%，P4/P5 和全部分类支路为0，符合代码设计。它已经学起来，V1 的“分支几乎休眠”解释不再适用于 V2。

代码读取 stride4 的 P2，PixelUnshuffle 后加入 stride8 的 P3 回归输入。原有8,400个预测位置不变，分类、正样本分配和质量评分监督不变。它能够改动局部回归特征，但没有直接解决低分数检出、高 IoU 框排序或混合场景 smoke 的问题。

隐藏16通道可能限制表达能力，但没有独立宽度消融证明它是主要原因。现在继续扩大通道或叠加分支的依据不足。

### context 的限制

相同8个 batch 的 P3/P4/P5 回归残差约40.26%/41.80%/22.78%，分类残差约34.93%/30.58%/10.35%。它明显参与预测，却只带来很小的额外收益。

原 n 模型已有 PAN、SPPF、C2PSA。额外多尺度融合可能与现有能力重叠；这是结合结构和结果的假设，不能仅凭残差幅度证明“冗余”或“过平滑”。新增分支仍使用原来的监督目标，没有直接约束严格定位质量排序。

## 3. 新发现：框质量排序具有值得验证的空间

本次做了两类需要 GT 的理想化诊断，均保留原来的 post-NMS 框和官方各 IoU 阈值的 TP 匹配结果。

1. 将分数改为原置信度×最大同类 GT IoU。baseline 从53.263%到60.301%。它同时压低了不匹配框的分数，不能把全部差值归因于定位质量排序。
2. 更严格的对照：先确定原 TP50 集合；每类只把这个集合已有的分数按真实 IoU 重新分配，FP50 的分数、全部框坐标和每类分数分布保持不变。AP50 精确保持不变。

| 第二类诊断 | 原 mAP50–95 | GT 质量排序后 | 诊断差值 | 原 fire AP75 | 排序后 fire AP75 |
|---|---:|---:|---:|---:|---:|
| baseline seed0 | 53.263% | 59.857% | +6.594点 | 45.895% | 58.640% |
| context seed0 | 53.482% | 60.127% | +6.645点 | 46.008% | 58.767% |

这是需要真实标签的 oracle 对照，包含对 TP50 身份和 IoU 的理想化知识，**不是部署结果、严格数学最优值或可实现增益预测**。它给出的有效信息是：即使不改变坐标，已有框的严格定位质量排序仍可以明显改变 mAP50–95，值得优先做一个可学习性实验。

几何缺口仍存在：baseline 在 conf=.001 时，fire 一对一 IoU.5/.75/.9 召回约96.44%/70.42%/21.21%。提高评分质量不能创造不存在的高 IoU 框。单靠评分实现+5点仍然困难。

YOLO 当前的 TAL 已用分类分数与 IoU 构造匹配和软分类目标，不能声称原模型完全没有质量监督。[当前版本 TAL 源码](https://github.com/ultralytics/ultralytics/blob/v8.4.42/ultralytics/utils/tal.py)。新设计检验的是：显式读取回归分布和回归特征，能否更准确地预测严格定位质量。GFLV2 提供了利用框分布统计进行轻量质量估计的研究依据，其 COCO 增益不能直接当成 FASDD 的预期增益。[GFLV2 原论文](https://arxiv.org/abs/2011.12885)

## 4. 下一轮主模块：显式定位质量评分

代码 `firesmoke/localization_quality.py` 已通过捕获原回归塔特征、保持锚点顺序的适配器接入真实 Detect；训练入口为 `scripts/train_fasdd_n_quality_stage3.py`。2026-10-10 已在 lxy 启动 Q0。结构如下：

```text
每个原预测位置：
  四边 DFL 分布 → 每边 top4 概率、归一化均值、熵 → 24维
  原 cv2 回归塔的64维特征 → 64→8 投影
  原两类分类概率 → 2维
  P3/P4/P5 标识 → 3维
  拼接37维 → 32维 SiLU → fire/smoke 两个质量 logit
  最终分数 = 原类别概率 × sigmoid(对应类别质量)
```

新增1,802参数；合计2,592,032，约比原 n 增加0.070%。原三个 stride8/16/32 检测层不变。完整集成后仍需实测延迟、导出和 NMS 行为，参数少不等于延迟已确认。

### Q0：冻结父模型的质量可学习性实验，优先执行

- 父模型：已完成 baseline seed0，所有模型参数和 BN 固定为 eval；质量输入和 IoU 目标 detach。
- 数据：只使用 train。按固定 ID 哈希划分90%拟合/10%内部验证；原 val/test 不用于拟合。
- 每图样本：原 TAL 正样本与原类别最大概率 top128 个位置取并集、去重，避免大量普通背景支配损失。
- 目标：每个预测框分别对 fire/smoke GT 求最大同类 IoU，作为软 BCE 标签；没有该类 GT 时目标为0。每图归一化样本权重。
- 固定 pilot：5轮、AdamW lr=.001、weight_decay=.0001、batch32、640，无几何/颜色增强。以 train 内部验证 BCE 选检查点。
- 选定的 readout 在全 val 报告三种模式：质量关闭；原 NMS 后评分；质量参与原 NMS 前评分。预先指定 NMS 前模式为主结果，NMS 后模式用于解释排序贡献，不能事后挑最高模式。
- 首轮自动保存每类 AP75/AP50–95、最终分数与 IoU 的相关性、父检查点前后 SHA 和模型/BN 不变证明。质量预测误差、16–64px 火焰、混合烟雾与背景告警列为完成后的详细审计项目，首轮自动报告尚未覆盖这些项。
- 预算门槛：主结果 mAP50–95 ≥+0.5点，并检查 fire 的高 IoU 收益与 smoke 退步。0.5点是继续投入训练预算的规则，不是统计显著性。

如果 readout 只学到原分类分数的单调变换，排序可能不会改善。若 Q0 没有有效收益，先检查质量预测是否有新信息，再决定是否转向定位蒸馏；不因梯度非零就安排相同机制的100轮实验。

### Q1：条件满足后，做100轮独立训练

与选定初始化政策下的同款 n 基线配对，只增加质量监督，原 box/cls/DFL 损失与 TAL 继续使用原始分类分数。首个联合训练分支仍将质量输入和目标 detach；质量 loss gain 固定.25。

实现时应保持原检测参数的梯度裁剪规则，质量参数独立裁剪，避免联合范数改变父模型有效梯度。之后“允许质量梯度回流”作为单独消融，不与首个分支同时改变。该阶段当前是完整设计，未实现或启动。

## 5. 平行对照：回归头预训练迁移

历史基线只迁移0–22层，原 cv2 回归塔和 DFL 等同检测头一起重置。静态兼容不证明它就是瓶颈，但这是与当前定位问题相关、代价明确的独立对照。

| 对照 | 额外迁移的头状态张量 | 状态元素 | 其他变化 |
|---|---:|---:|---|
| T0，原政策 | 0 | 0 | 可按需要复跑控制 |
| T1，reg_transfer | 43 | 382,678 | 仅迁移兼容 cv2/DFL，分类初始化保持与 T0 一致 |
| T2，compatible | 70 | 388,514 | 在 T1 外增加同名同形状的其他头状态，作为后续消融 |

以上元素包含 BN 缓冲，不能当成可训练参数数量。两个新对照均为原2,590,230参数 YOLO11n。

入口已实现为 `scripts/train_fasdd_n_stage3.py`，配置为 `configs/protocol-fasdd-n-stage3.yaml`，两边已通过 dry-run 的数据、权重和 CUDA 检查。T1 建议在 cmj，与 lxy 的 Q0 主模块 pilot 并行；T2 保留为后续对照。

训练配方仍为640/batch32/SGD/100轮/seed0/AMP=false，源码、协议、迁移逐键决策和终态记录均保存。原训练器及 V2 结果保持原始证据。

```bash
python scripts/train_fasdd_n_stage3.py --method reg_transfer --seed 0 --dry-run
python scripts/train_fasdd_n_stage3.py --method reg_transfer --seed 0 --execute

# 后续兼容迁移消融：
python scripts/train_fasdd_n_stage3.py --method compatible --seed 0 --dry-run
```

此入口前台执行，由外部 supervisor 将日志保存到项目外 runtime。训练输出为 `results/fasdd_cv_clean_v1/fasdd-n-stage3/<method>/seedN/`。T1 已于2026-10-10在 cmj 启动，100轮、seed0。启动详情见 `docs/FASDD_N_STAGE3_SEED0_RUNS_20261010.md`。

## 6. 定位蒸馏和数据审核的触发条件

如果质量评分 pilot 无法提取有效质量信号，或仍需要提高真实几何定位，先建立同数据、更强教师的对照；教师须在 fire AP75 至少高3点、整体 mAP50–95 至少高2点，再进入蒸馏。这里的门槛同样是预算规则。

最终部署仍为 n；较大教师只用于训练。第一项独立蒸馏是相同 stride8/16/32 位置上的 DFL 分布 KL，温度2，以 GT 一致且教师定位可靠的位置作选择，训练与部署预处理保持一致。分类蒸馏随后单独加入。定位分布蒸馏可在不增加学生推理结构的情况下传递定位信息，但论文结果不能保证当前任务收益。[Localization Distillation 原论文](https://arxiv.org/abs/2204.05957)

训练集审核清单已经生成：300个互不重复 train ID，中小火焰/混合场景/背景各100张；候选池分别为6,633/8,224/19,525。清单是固定哈希顺序的分层样本，组顺序会排除已选 ID，不代表数据自然频率。目前全部 pending，未修改任何标签。

审核应确定火簇合并/拆分、烟羽边界、透明区域、工业烟羽类别定义和遗漏/重复框。原 FASDD_CV 来自多来源图像，官方划分随机生成，不能默认场景独立。[FASDD 正式论文](https://www.tandfonline.com/doi/full/10.1080/10095020.2024.2347922)。现有感知近重复审核仍 pending；没有证据可以把全部定位误差归咎于标注。

数据改动独立建立训练数据版本、保存原标签与修订映射，用同配方比较；模型模块与数据修订分别归因。val 标签保持固定。明确有效候选后再做三seed配对确认；原 baseline 仍需补 seed2。最终+5点按相同数据/评估口径的配对均值判断。
